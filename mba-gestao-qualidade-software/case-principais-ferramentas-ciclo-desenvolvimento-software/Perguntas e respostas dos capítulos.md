## Perguntas de fixação

**1. O que significa CASE?**
CASE significa **Computer-Aided Software Engineering**, ou seja, **Engenharia de Software Auxiliada por Computador**. São ferramentas que apoiam atividades como análise, modelagem, desenvolvimento, testes e documentação de software.

**2. Qual a diferença entre Upper CASE e Lower CASE?**
**Upper CASE** apoia as fases iniciais do desenvolvimento, como levantamento de requisitos, análise, modelagem e projeto.
**Lower CASE** apoia as fases finais, como implementação, geração de código, testes, manutenção e documentação técnica.

**3. Por que o levantamento de requisitos é uma etapa crítica?**
Porque define o que o sistema deve fazer e quais restrições deve atender. Erros nessa fase podem gerar retrabalho, aumento de custo, atrasos e um sistema que não atende às necessidades do usuário.

**4. Qual a diferença entre requisito funcional e requisito não funcional?**
**Requisito funcional** descreve uma função do sistema, por exemplo: cadastrar cliente, emitir relatório ou autenticar usuário.
**Requisito não funcional** descreve características de qualidade ou restrições, como desempenho, segurança, usabilidade, disponibilidade e escalabilidade.

**5. Para que serve uma ferramenta ALM?**
Uma ferramenta **ALM**, Application Lifecycle Management, serve para gerenciar o ciclo de vida da aplicação, acompanhando requisitos, tarefas, código, testes, versões, releases, defeitos e manutenção.

**6. O que é um wireframe?**
Wireframe é um esboço visual de uma tela ou interface. Ele mostra a estrutura básica da página, a posição dos elementos e o fluxo de navegação, antes do design final.

**7. Qual a função de um SGBD em uma aplicação?**
O **SGBD**, Sistema Gerenciador de Banco de Dados, é responsável por armazenar, organizar, consultar, alterar e proteger os dados usados pela aplicação.

**8. Qual o papel do DBA em um sistema de software?**
O **DBA**, Database Administrator, administra o banco de dados. Ele cuida de segurança, permissões, backup, restauração, desempenho, integridade dos dados e disponibilidade do banco.

**9. Por que a UML é importante na modelagem orientada a objetos?**
Porque a **UML** permite representar visualmente classes, objetos, relacionamentos, casos de uso, estados e interações. Isso facilita a comunicação entre analistas, desenvolvedores e demais envolvidos no projeto.

**10. Como ferramentas CASE podem melhorar a qualidade de um projeto?**
Elas melhoram a qualidade ao padronizar documentos e modelos, reduzir erros manuais, gerar artefatos automaticamente, melhorar a rastreabilidade dos requisitos e facilitar a manutenção do sistema.

## Perguntas de revisão

**1. Qual é a diferença entre implementação, testes e entrega final?**
**Implementação** é a construção do sistema por meio do código.
**Testes** verificam se o sistema funciona corretamente e atende aos requisitos.
**Entrega final** é a disponibilização do sistema pronto para o usuário ou cliente.

**2. O que é uma release?**
Release é uma versão do software disponibilizada para uso, podendo conter novas funcionalidades, correções, melhorias ou ajustes.

**3. Por que o controle de versionamento é importante no processo de manutenção?**
Porque permite acompanhar o histórico de alterações, recuperar versões anteriores, trabalhar em equipe, criar branches, corrigir erros com segurança e controlar o que foi modificado no sistema.

**4. Qual é a diferença entre teste alfa e teste beta?**
**Teste alfa** é feito internamente, normalmente pela equipe de desenvolvimento ou usuários controlados.
**Teste beta** é feito por usuários reais ou externos, em um ambiente mais próximo do uso final.

**5. Em que cenário o Selenium é mais indicado?**
O Selenium é mais indicado para automação de testes em aplicações web, simulando ações do usuário no navegador, como clicar, preencher campos e validar telas.

**6. Por que o JMeter é adequado para testes de carga?**
Porque o JMeter permite simular muitos usuários acessando uma aplicação ao mesmo tempo, avaliando desempenho, tempo de resposta, estabilidade e capacidade do sistema sob carga.

**7. Qual é o papel do Appium na automação mobile?**
O Appium é usado para automatizar testes em aplicações móveis, principalmente Android e iOS, permitindo simular interações como toque, digitação, navegação e validação de telas.

**8. Como o Cucumber ajuda a aproximar equipe técnica e área de negócio?**
O Cucumber usa uma linguagem próxima da linguagem natural, geralmente no formato **Dado, Quando, Então**. Isso permite que regras de negócio sejam descritas de forma compreensível tanto para desenvolvedores quanto para pessoas da área de negócio.

**9. Para que tipo de aplicação o Robotium foi projetado?**
O Robotium foi projetado para automação de testes em aplicações Android, especialmente testes funcionais e de interface.

**10. Por que testes automatizados ajudam em ciclos de regressão?**
Porque permitem executar novamente os testes de forma rápida e repetitiva após alterações no sistema, ajudando a identificar se uma funcionalidade que antes funcionava passou a apresentar erro.
