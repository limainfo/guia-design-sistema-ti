# 📘 System Design em Pouco Tempo

### *Guia Rápido e Essencial para Entrevistas de Arquitetura de Sistemas*

Aprenda System Design de forma acelerada. Este guia reúne os conceitos essenciais necessários para você ir bem em uma entrevista de system design — material criado por hiring managers e staff engineers de empresas FAANG.

Muitas pessoas chegam até nós com entrevistas marcadas em alguns dias — ou até no dia seguinte. Vamos ser sinceros: ninguém se torna especialista da noite para o dia.
Por isso criamos o **System Design em Pouco Tempo**: com dados de centenas de entrevistas simuladas, identificamos os principais erros, lacunas e pontos de atenção. Assim, você pode evitar armadilhas comuns e apresentar um desempenho sólido.

O objetivo aqui é cobrir **os 20% mais importantes** — aqueles que dão 80% do resultado.
Este guia não busca ensinar tudo do zero, e sim acelerar sua preparação com conteúdo direto, prático e de alto impacto.

# 🧭 Como Usar Este Guia

Preparar-se para entrevistas de system design significa montar um conjunto de peças:

* **Core Concepts:** o alicerce.
* **Key Technologies:** ferramentas modernas utilizadas em sistemas reais.
* **Patterns:** soluções recorrentes para problemas clássicos.
* **Delivery Framework:** como estruturar sua resposta para impressionar o entrevistador.
* **Prática:** como resolver problemas reais e responder perguntas difíceis.

Se você tem pouco tempo, siga esta ordem de prioridade:

1. **Leia atentamente o Delivery Framework**
2. **Passe rapidamente pelos Key Technologies**
3. **Reserve o resto do tempo para os Core Concepts**

# 🧩 Tipos de Entrevista em System Design

Existem quatro categorias principais. Elas se sobrepõem, mas variam em profundidade, propósito e foco.

---

## 1️⃣ **Product Design (mais comum)**

Você projeta o sistema por trás de um produto real.

**Exemplos de perguntas:**

* Projetar um sistema de corrida como Uber
* Construir um chat como Slack
* Criar uma rede social como Facebook

✔ Este guia é totalmente aplicável para esse tipo.

---

## 2️⃣ **Infrastructure Design**

Aqui o foco é mais profundo, envolvendo armazenamento distribuído, resiliência e algoritmos de consenso.

**Exemplos:**

* Criar um rate limiter
* Projetar um message broker
* Criar um banco chave-valor

✔ Este guia ajuda, mas você deve enfatizar os **Conceitos**.

---

## 3️⃣ **Object Oriented Design (Low-Level Design)**

Comum em empresas como Amazon.
O foco é em classes, SOLID, relacionamentos e fluxos internos.

❌ Este guia não cobre OOD.
Recomendação: *Grokking the Low Level Design Interview*.

**Exemplos:**

* Sistema de estacionamento
* Máquina de vendas
* Controlador de elevador

---

## 4️⃣ **Frontend Architecture Design**

Voltado para aplicações complexas (planilhas, editores visuais, vídeo).

❌ Este guia não cobre este tipo.
Recomendação: *Great Frontend*.

# 📝 Como Você Será Avaliado

Embora variações existam entre empresas, quatro pilares são padrão:

---

## ⭐ 1. **Navegação do Problema**

Avalia sua capacidade de:

* Explorar requisitos
* Priorizar corretamente
* Dividir em componentes
* Conduzir a conversa

💥 Erros comuns:

* Ignorar requisitos importantes
* Focar no trivial
* Travar em detalhes irrelevantes

---

## ⭐ 2. **High-Level Design**

Querem ver se você domina **como montar a solução completa**.

Erros comuns:

* Falta de conceitos fundamentais
* Não considerar escala
* Uma arquitetura confusa ("espaguete")

---

## ⭐ 3. **Excelência Técnica**

Avalia sua capacidade de aplicar:

* Tecnologias modernas
* Boas práticas
* Patterns adequados

Erros comuns:

* Não conhecer ferramentas essenciais
* Confundir tecnologias
* Aplicar padrões sem propósito

---

## ⭐ 4. **Comunicação & Colaboração**

Entrevistas são colaborativas. Querem avaliar:

* Clareza
* Didática
* Reação a perguntas
* Capacidade de ajustar a solução

Erros comuns:

* Falar de forma difícil
* Ficar na defensiva
* Se perder nos detalhes
